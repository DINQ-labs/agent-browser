# HTTP Bridge

The HTTP bridge runs agent-browser as a long-lived service and exposes a small JSON API for:

- Creating isolated browser sessions
- Sending commands to a specific session over HTTP

It manages one daemon per session and forwards commands over the same JSON socket protocol the CLI uses.

## Run Locally

```bash
cd bridge
pnpm install
pnpm run build
BRIDGE_PORT=3000 pnpm start
```

## Docker

Build from the repository root:

```bash
docker build -t agent-browser-bridge .
docker run --rm -p 3000:3000 agent-browser-bridge
```

The container starts an embedded Xvfb server so `headless: false` sessions work without a real display.

### Example (curl)

```bash
curl -s http://localhost:3000/health

curl -s -X POST http://localhost:3000/sessions \
  -H 'Content-Type: application/json' \
  -d '{"session":"t1","headless":true}'

curl -s -X POST http://localhost:3000/sessions/t1/commands \
  -H 'Content-Type: application/json' \
  -d '{"action":"navigate","url":"https://example.com"}'

curl -s -X POST http://localhost:3000/sessions/t1/commands \
  -H 'Content-Type: application/json' \
  -d '{"action":"title"}'

## Screenshots

The daemon writes screenshots to a file path on the bridge host/container.

- File path (local to bridge): `{"action":"screenshot"}`
- Bytes inline (remote-friendly): `{"action":"screenshot","encoding":"base64"}` → `data.screenshot`

```bash
curl -s -X POST http://localhost:3000/sessions/t1/commands \
  -H 'Content-Type: application/json' \
  -d '{"action":"screenshot","encoding":"base64"}'
```

curl -s -X DELETE http://localhost:3000/sessions/t1
```

## Session launch fields

`POST /sessions` accepts the same daemon launch fields used by `agent-browser` internally.

<table>
  <thead>
    <tr><th>Field</th><th>Description</th></tr>
  </thead>
  <tbody>
    <tr><td><code>runtime</code></td><td><code>patchright</code> (default) or <code>camoufox</code>.</td></tr>
    <tr><td><code>profile</code></td><td>Persistent browser profile directory path.</td></tr>
    <tr><td><code>storageState</code></td><td>Either a JSON file path or an inline storage state object.</td></tr>
    <tr><td><code>sessionName</code></td><td>Auto-save/load state persistence name.</td></tr>
    <tr><td><code>userAgent</code></td><td>Override user agent for the session.</td></tr>
    <tr><td><code>viewport</code></td><td>Initial viewport size for the session.</td></tr>
  </tbody>
</table>

Example:

```bash
curl -s -X POST http://localhost:3000/sessions \
  -H 'Content-Type: application/json' \
  -d '{
    "session":"t1",
    "runtime":"camoufox",
    "profile":"/tmp/camoufox/linkedin_user_123",
    "sessionName":"linkedin_user_123",
    "storageState":{"cookies":[],"origins":[]},
    "headless":true
  }'
```

Inline <code>storageState</code> objects are written to a temporary file by the bridge and forwarded to the daemon through <code>AGENT_BROWSER_STATE</code>.

## Camoufox runtime

- Patchright remains the default runtime.
- Set <code>"runtime":"camoufox"</code> only when you explicitly want the Camoufox Firefox runtime.
- Camoufox does not support Chromium-only features such as extensions and <code>--allow-file-access</code>.
- If the Camoufox binary is missing, install it with <code>npx camoufox-js fetch</code>.
- The experimental native Rust daemon currently returns <code>Not yet implemented: camoufox runtime in native daemon</code> for Camoufox launches.
